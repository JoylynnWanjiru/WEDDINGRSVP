# Wedding RSVP & Guest Management

A private, personalised wedding website and guest-management system in **burgundy, gold & white**. It replaces printed invitation cards.

- Every guest gets a **personal invitation link** by email and WhatsApp.
- The couple can see who **received, opened and viewed** their invitation.
- Guests **RSVP**, including named extra guests within a seat allowance.
- The couple **approves or revokes** each guest's attendance.
- Approved guests get a **QR gate pass**, which ushers scan at the gate.
- Venue, live location, programme and all other details are shown **only to approved guests**.
- An admin dashboard shows **headcount, dietary needs and arrivals** live.

> **Privacy rule:** the public sees only a teaser and a "request an invitation" form. Saying "Yes" unlocks nothing; only the couple's approval does. Access is checked on the server on every request, so locked content never reaches an unapproved visitor's browser.

## Tech stack

| Area | Choice |
|---|---|
| Framework | Next.js 16 (App Router) + TypeScript |
| Styling | Tailwind CSS v4, with theme tokens as CSS variables |
| Database | Neon Postgres + Drizzle ORM |
| Validation | Zod |
| Email | Nodemailer + Gmail SMTP, React Email templates |
| WhatsApp | `wa.me` click-to-chat links (free, sent from your own phone) |

| Tokens & sessions | `jose` (signed JWTs, HTTP-only cookies) |
| Hosting | Vercel Hobby (free), auto-deployed from GitHub |

**Backend first.** All logic lives in `server/` and is tested directly, without a browser. Pages, server actions and `app/api` routes are thin wrappers that call `server/services`, so the backend works and is tested before the frontend is built.

**Rules to follow when adding code:**

1. **Locked content goes through `server/services/access.ts`.** Any page, server action, API route or email that returns story, programme, venue, dress code, FAQ, contacts, pass or day-of data must call `requireApproved(token)` *before* it fetches that data (BLUEPRINT BR-1 to BR-4).
2. **Status changes go through `server/domain/status.ts`.** It holds the lifecycle from BLUEPRINT §5, and every change is logged.
3. **Nothing couple-specific is hard-coded.** Names, dates, venues, programme, colours and photos come from the database or config. That keeps the codebase usable as a template for other couples later.

## Getting started

**Prerequisites:** Node.js 24+ (it ships npm 11; npm 10 rejects this lock file), a free [Neon](https://neon.tech) database, and a Gmail account with 2-Step Verification (for an app password).

```bash
git clone https://github.com/JoylynnWamjiru/WEDDINGRSVP.git
cd WEDDINGRSVP
npm install
npm test                       # runs every backend rule test; needs no database or .env
cp .env.example .env.local     # then fill in the values
npm run db:migrate             # create the tables in your Neon database
npm run db:seed                # one wedding with placeholder content
npm run dev                    # http://localhost:3000
```

Tests run against PGlite (Postgres in memory), so they need no account, network or secrets.

### Environment variables

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Neon connection string |
| `APP_URL` | Public site URL, e.g. `https://<project>.vercel.app` |
| `TOKEN_SECRET` | At least 32 random characters. Personal links and passes are derived from it, so **changing it invalidates every link and pass already sent** |
| `ADMIN_PASSWORD_HASH` | Output of `npx tsx scripts/hash-password.ts <password>` |
| `GMAIL_USER` | Gmail address that sends invitations |
| `GMAIL_APP_PASSWORD` | Gmail app password |
| `CRON_SECRET` | Protects `/api/cron/*` |
| `WEDDING_SLUG` | Optional. Which wedding the public pages show; defaults to `our-wedding` (the seeded one) |

Never commit `.env.local`. Add the same variables in **Vercel → Project → Settings → Environment Variables**.

> **Security:** secrets and real guest data never go in the repo. `.gitignore` blocks env files, keys, guest-list CSVs (except the template), spreadsheets and database dumps, and CI scans every push with [gitleaks](https://github.com/gitleaks/gitleaks). If a secret is ever committed, **rotate it immediately**. Deleting the commit is not enough.

## Deployment

1. Push to `main` on GitHub.
2. Import the repo in Vercel (Hobby plan) and add the environment variables.
3. Every push to `main` deploys to production. Pull requests get preview URLs.
4. The cron jobs in `vercel.json` run once a day (the Hobby plan limit).

### Forgot the admin password?

Run `npx tsx scripts/hash-password.ts <new-password>`, replace `ADMIN_PASSWORD_HASH` in Vercel's environment variables, and redeploy.

### Guest list import

Use [`public/templates/guest-list-template.csv`](public/templates/guest-list-template.csv). Phones can be written as `07…`, `7…` or `254…`; they are stored as `+254…`.
